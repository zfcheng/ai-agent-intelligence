## Key Updates

- **生产性能回归有了部署后复核。** OpenAI 在 11 月 19 日披露，Performance Factory 让诊断、候选修复、工程师审阅和部署后验证共用一条任务记录。部署事件唤醒另一个 Agent 核查基线。评测这类流程可以分开统计“修复获合并”和“生产指标恢复”，并查看两者之间的失败案例。[OpenAI 工程原文](https://openai.com/index/how-openai-performance-factory-keeps-chatgpt-fast/)
- **模型退役影响存量 Agent。** Google Cloud 为 Gemini 3.6 Flash 列出的退役日是 11 月 19 日，建议迁往 3.8 Flash。仍固定旧模型 ID 的工作流，应先核对实际路由，再用历史工具调用轨迹检查迁移后的参数、轮次及只读任务是否出现写入。本条记录生命周期节点；官方页面未提供每个端点的实时状态。[Google Cloud 模型生命周期](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-6-flash)

## 论文与讨论

11 月 19 日 02:27（上海），一项 cs.AI 预印本提交了本地电力电子仿真 Agent 的测量框架，从建模、运行仿真到验证规格，统计用时、能耗、token 和每个解成任务的成本。对内网部署可直接借用的是分母：把失败尝试的成本也计入总投入，再除以验收成功数。[论文与提交记录](https://arxiv.org/abs/2611.24880)
