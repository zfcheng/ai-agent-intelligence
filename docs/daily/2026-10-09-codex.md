## Key Updates

- LangChain's October 8 case study on Snyk Assist is the day's most useful production signal: Snyk moved an internal support agent into its core product, kept one LangGraph runtime across Slack, web, and API surfaces, attached tools by user permissions, persisted state with a PostgreSQL checkpointer, and made LangSmith traces the basis for offline evals, CI gates, online grading, and dataset creation. The reported production result is material: 60,000+ queries, 500+ customer accounts, 85%+ sessions resolved without a support ticket, and 250+ cases auto-detected and escalated. Source: [LangChain/Snyk case study](https://dev48.org/en/articles/how-snyk-turned-an-internal-support-agent-into-a-customer-feature).
- LangChain also shipped two adjacent Deep Agents updates that push agents closer to durable internal teammates: Managed Deep Agents v0.9 adds agent-created schedules, per-run model/tool/skill configuration, and Slack reactions, while the payment demo shows a Slack agent using Stripe Link plus Machine Payments Protocol with explicit user approval and budget caps. Treat this as a pattern library for internal agents: identity-bound schedules, per-channel tool scopes, human approval for irreversible actions, and payment credentials kept out of model context. Sources: [Managed Deep Agents v0.9](https://www.langchain.com/blog/managed-deep-agents-schedules-per-run-configuration-slack), [agents that can pay](https://www.langchain.com/blog/agents-that-can-pay-with-stripe-link).
- Agent skills are becoming an operational packaging format, not just prompt snippets. LangChain's Deep Agents skill revamp emphasizes progressive disclosure, binding tools to skills so tools load only when the skill is read, pinning skills at runtime, and reloading skills mid-thread; this directly supports large internal skill libraries without stuffing every tool and instruction into the initial context. Source: [Revamping Skills in Deep Agents](https://dev48.org/en/articles/revamping-skills-in-deep-agents).

## Hot Discussions

- The most active production debate remains security inheritance: an October 7 analysis of recent agent incidents argues agents often amplify existing access, sandbox, credential, and environment mistakes rather than creating wholly new risk categories. For private-cloud or enterprise rollout, the practical implication is to audit inherited permissions, eval sandboxes, tool credentials, and network egress before adding higher-order "agent governance" layers. Source: [TechRadar Pro](https://www.techradar.com/pro/ai-agents-dont-create-new-risk-they-inherit-it).
- OpenAI's Evals platform deprecation is now a near-term migration item: docs say existing Evals become read-only on October 31, 2026 and are scheduled to shut down on November 30, 2026, with newer dataset-oriented workflows suggested for iteration. Teams still using hosted OpenAI Evals should export definitions/results and move agent regression suites into repo-owned harnesses or another eval platform before the end-of-month freeze. Source: [OpenAI evals guide](https://developers.openai.com/api/docs/guides/evals).

## Actionable Insight

- Today's signal favors a "production harness first" roadmap: standardize one agent runtime with typed permission-scoped tools, persisted state, trace-to-dataset conversion, PR-level eval gates, and online grading before expanding autonomous actions. For internal R&D agents, the next useful experiment is not another demo agent; it is a small Snyk-style support or ops assistant with one irreversible action behind human approval, one scheduled follow-up, and an eval suite that blocks regressions in CI.
