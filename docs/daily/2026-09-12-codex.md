## Key Updates

- The previous US business day kept shifting the agent conversation from demos to governance: Harness surfaced the enterprise "confidence gap" around AI agents, with buyers claiming agent inventories while active discovery, ownership, policy gates, and runtime controls lag. This aligns with Harness's own Autonomous SDLC positioning around policy-based autonomy, audit trails, RBAC, human approvals, runtime protection, AI evals, and cost attribution. [Harness](https://www.harness.io/) / [AI Agent Store](https://aiagentstore.ai/)
- Agent infrastructure is consolidating into gateways and control planes. TrueFoundry is explicitly packaging LLM gateway, MCP gateway, and Agent Gateway around routing, fallbacks, rate limits, access control, auditability, tracing, and VPC/on-prem deployment, while the Agentic AI Foundation highlighted `agentgateway` as an open data-plane alternative for enterprise LLM/tool traffic. [TrueFoundry](https://www.truefoundry.com/) / [Agentic AI Foundation](https://home.mlops.community/)
- The most relevant new research signal was "Scanning the Harness," a Sep. 7 arXiv study of 3,171 public coding-agent setups and skill collections: 16.0% carried a confirmed security defect, including unpinned MCP servers, scoped-looking pre-approval of arbitrary execution, and skills that pre-approve shell access. This is directly actionable for Codex/Claude Code/Cursor-style internal harness governance. [arXiv](https://arxiv.org/abs/2609.07360)

## Hot Discussions

- The hot US-day debate was "who controls the agent?" Security coverage framed agent control planes as an identity and threat-intelligence problem, not only an LLM-safety problem: agent identity, access revocation, tool permissions, MCP/A2A governance, traceability, and accountable owners are becoming the default enterprise vocabulary. [Security Point Break](https://securitypointbreak.com/)
- Observability vendors are also reframing for agent-era operations. Dash0's OpenTelemetry-native pitch emphasizes one signal store queried by humans and agents through PromQL, SQL, CLI, API, and MCP; the practical implication is that production agents should inspect the same traces/logs/metrics humans rely on, rather than a separate opaque "AI ops" pane. [Dash0](https://www.dash0.com/)

## Actionable Insight

- Treat this as a harness hardening day: inventory every internal agent, MCP server, skill, hook, and pre-approved command; require version pins and least-privilege grants; route production tool access through an auditable gateway; and add regression/eval gates before giving agents deployment, incident, or data-plane privileges. The useful maturity metric is no longer "agent solved the task," but whether the model-harness-environment system produced a verifiable episode package with permissions, traces, checks, and accountable intervention points. [AI Harness Engineering](https://arxiv.org/abs/2605.13357)
