## Key Updates

- LangChain's October 7 releases pushed the "agent teammate" pattern further into production operations: [Managed Deep Agents v0.9](https://www.langchain.com/blog/managed-deep-agents-schedules-per-run-configuration-slack) added agent-created schedules, per-run model/skill/tool/sandbox configuration, and Slack acknowledgements; [Deep Agents skills](https://www.langchain.com/blog/revamping-skills-in-deep-agents) added tool-bound skills, pinned skills, and mid-thread skill reloads. The important move is deterministic runtime scoping: one deployment can serve multiple teams while constraining which tools and skills are visible before the model acts.
- The evaluation stack kept converging on trace-level and trajectory-level assessment rather than final-answer scoring. OpenAI's agent-eval guidance emphasizes traces, graders, datasets, and eval runs for workflow-level checks such as tool choice, handoffs, policy violations, and routing changes ([OpenAI docs](https://developers.openai.com/api/docs/guides/agent-evals)); Arize's October 7 update similarly frames production agent evals around routing, tool arguments, trajectories, repeated-run reliability, and path convergence ([Arize guide](https://arize.com/ai-agents/agent-evaluation/)).
- LangSmith's late-September trajectory work stayed relevant in the U.S. daytime discussion because it addresses a practical review bottleneck: long-running sessions can be read as ordered behavioral paths, then scored, annotated, saved to datasets, or inspected in the underlying trace when a step looks wrong ([LangSmith Trajectories](https://www.langchain.com/blog/langsmith-trajectories-tracing)). This is the same loop teams need for regression gates: production traces -> readable failures -> labeled cases -> eval datasets.

## Hot Discussions

- Agent oversight is now being treated as a security surface, not just a debugging feature. METR's safer-evals monitor design explicitly flags attempts to disable monitoring, manipulate prompts/config, or delete, truncate, or redirect transcripts/logs ([METR note](https://metr.org/notes/2026-09-27-implementing-a-basic-blocking-action-monitor/)); Inspect's security policy also treats code execution or file access triggered by reading eval logs, transcripts, or datasets as in-scope vulnerabilities ([Inspect security policy](https://github.com/UKGovernmentBEIS/inspect_ai/blob/main/SECURITY.md)). Takeaway: trace viewers and transcript renderers must be hardened like production admin consoles.
- Enterprise agent-infrastructure talk centered on controlled persistent sandboxes plus auditability. VAST's October 7 piece argues that useful agents need bounded runtimes, fast access to current enterprise data, MCP-style action surfaces, and an observability layer recording what they accessed, produced, and did ([VAST Data](https://www.vastdata.com/blog/how-do-you-keep-enterprise-ai-agents-under-control)). This aligns with the broader agentic-infra direction: autonomy increases only when authority, persistence, and evidence are engineered together.

## Actionable Insight

- For private-cloud or enterprise pilots, make the next increment an "agent harness contract": per-run tool/skill allowlists, identity-scoped schedules, tamper-resistant raw logs, readable trajectories for SME review, and CI evals that check tool choice, arguments, policy boundaries, final state, and path convergence. The strongest signal from the day is that production maturity is shifting from smarter planners to bounded execution plus repeatable evidence.
